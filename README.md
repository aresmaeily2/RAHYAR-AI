# رهیار AI (Rahyar AI) — دستیار هوشمند شخصی

**رهیار AI** دستیار هوشمند شخصی فارسی‌زبان (RTL) برای مدیریت و **انجام** کارهاست — «از درخواست تا انجام». پاسخ دستیار فقط متن نیست؛ می‌تواند مستقیماً روی داده کاربر اثر بگذارد (ثبت/تکمیل/حذف کار، یادآوری، تجزیه، حافظه بلندمدت) و نتیجه هر اقدام را ثبت می‌کند.

> نام یکپارچه محصول و پکیج در نسخه ۱٫۰: **Rahyar / رهیار AI** — در `package.json`، README، عنوان پنجره، Manifest، PWA، آیکون‌ها و مستندات یکسان است.

## فناوری‌ها

- **Next.js 16 (App Router) + React 19 + TypeScript (strict)**
- **Prisma 6 + SQLite** (`db/custom.db`) — مناسب استقرار شخصی
- **Zustand** + **Tailwind 4 + shadcn/ui**
- **z-ai-web-dev-sdk** — فقط داخل `src/lib/ai.ts` و فقط از مسیر **AI Gateway** قابل استفاده
- فونت وزیرمتن خودمیزبان؛ بدون درخواست ثالث

## نصب و اجرا

```bash
# پیش‌نیاز: bun (یا node 20+)
cp .env.example .env        # تنظیم DATABASE_URL
bun install
bun run db:generate
bun run db:push             # ساخت/همگام‌سازی جداول — برای تغییرات افزایشی امن است
bun run dev                 # توسعه — پورت 3000

# انتشار
bun run build
bun run start               # اجرای بیلد standalone
```

**راه‌اندازی اولیه:** اولین بازدید از `/login` فرم «راه‌اندازی اولیه» مالک را نشان می‌دهد (نام کاربری، نام نمایشی، رمز ≥۸ نویسه). این فرم فقط یک‌بار و فقط وقتی حساب مالک هنوز رمز ندارد ظاهر می‌شود.

داده نمونه (seed) فقط برای کاربرِ در حال بارگذاریِ نخست و فقط اگر کارهای او خالی باشد ساخته می‌شود؛ داده واقعی کاربر هرگز حذف نمی‌شود.

> **دقت مهم درباره `prisma db push`:** برای تغییرات افزایشی امن است؛ برای تغییرات مخرب هشدار و تأیید می‌خواهد. **پیش از هر تغییر اسکیما بکاپ بگیرید** (`bun run backup`) و از `--accept-data-loss` استفاده نکنید (این پرچم عمداً از اسکریپت حذف شده است).

## معماری AI کم‌هزینه (بخش ۶ دستور)

```
رابط کاربر → API امن (نشست + گاردها) → AI Gateway مرکزی → مدل
                                          ├─ کلید قطع اضطراری (env یا Setting)
                                          ├─ سقف ورودی/خروجی
                                          ├─ سهمیه: کاربر/روز، کاربر/ماه، سامانه/روز
                                          ├─ حداکثر ۱ retry فقط خطای گذرا
                                          └─ ثبت مصرف (فراداده، بدون متن خصوصی)
```

- **اول قطعی، بعد مدل:** ثبت کار/گزارش/لیست با قواعد فارسی اجرا می‌شود و مدل فراخوانی نمی‌شود.
- **سهمیه تمام شود:** پیام شفاف فارسی + امکانات بدون مدل همچنان کار می‌کنند؛ هیچ مسیر پولی مخفی وجود ندارد.
- **کلید قطع:** `RAHYAR_AI_DISABLED=1` یا رکورد Setting `ai_kill_switch=1`.
- **سقف‌ها** با env: `AI_USER_DAILY_LIMIT` (پیش‌فرض ۶۰)، `AI_USER_MONTHLY_LIMIT` (۹۰۰)، `AI_SYSTEM_DAILY_LIMIT` (۳۰۰)، `AI_MAX_INPUT_CHARS` (۲۴هزار)، `AI_MAX_OUTPUT_CHARS` (۴هزار).
- **ارائه‌دهنده:** z-ai (کیفیت فارسی خوب + سهمیه پلتفرمی). ارائه‌دهنده دوم فقط با مزیت اثبات‌شده و تصمیم مالک اضافه می‌شود.

## قرارداد ابزارهای دستیار

| اکشن | گارد | ثبت نتیجه |
|---|---|---|
| add_task | پاک‌سازی + رزولو تاریخ + سقف طول | ActionLog (success/failed) + idempotency |
| complete/delete/update/star/snooze_task | حذف فقط با فعل صریح؛ حداکثر ۱ حذف در پیام | ActionLog |
| plan_day / breakdown_task | سقف ۳۰؛ مسیر Gateway | ActionLog + AiUsage |
| remember/forget | سقف ۱۰۰؛ فراموشی فقط با فعل صریح | ActionLog |
| add_reminder | سقف ۵۰ فعال؛ رد گذشته/خیلی دور | ActionLog |

## مدل داده (Prisma/SQLite)

- `User` + `Session` (توکن هش‌شده، انقضای ۳۰ روز) — راه‌اندازی اولیه مالک
- `Task`، `Subtask`، `Reminder`، `ChatMessage`، `Memory`، `Setting` — همه با `userId` (NOT NULL)
- `AiUsage` — فراداده مصرف مدل (بدون محتوا)
- `ActionLog` — نتیجه اقدامات + `idempotencyKey` یکتا

## سیاست امنیت

- **احراز هویت:** scrypt (N=16384) + نمک؛ توکن ۳۲ بایتی که فقط SHA-256 آن در DB است؛ کوکی `rahyar_session` (httpOnly، sameSite=lax، secure در تولید، ۳۰ روز).
- **جداسازی داده:** همه کوئری‌های API با `userId` کاربر نشست اسکوپ می‌شوند؛ دسترسی به کار/یادآور/زیرکارِ کاربر دیگر → ۴۰۴. ستون‌ها NOT NULL در سطح DB.
- **دو لایه گیت نشست:** middleware (حضور کوکی، Edge) + `requireUser()` در هر مسیر (اعتبارسنجی واقعی DB).
- **ورود:** سقف ۱۰ تلاش/دقیقه؛ پیام خطای عمومی بدون افشای وجود حساب.
- دفاع‌های حفظ‌شده: CSP nonce + strict-dynamic، Same-Origin + Sec-Fetch-Site، rate limit، مهار استریمی بدنه ۱۰۰KB، دیوار `<user_data>` علیه تزریق پرامپت، بدون HTML خام در مارک‌داون.
- **اعتماد به پروکسی:** `TRUST_PROXY_HEADERS≠0` فقط پشت پروکسی معتبر (Caddy). استقرار مستقیم → `0`.
- **اسرار و داده در گیت:** `.env`، `db/`، `backups/`، `artifacts/` از ایندکس خارج‌اند. در تاریخچه قدیمی مخزن بلاب‌های حساس مانده — پاک‌سازی فقط با تأیید مالک و پیش از هر push.
- **لاگ‌ها:** بدون محتوای خصوصی کاربر.

## محدودیت‌های شفاف

1. **انتشار عمومی:** با احراز هویت و جداسازی فعلی بهتر شده، اما برای اینترنت عمومیِ باز هنوز توصیه نمی‌شود: rate limit درون‌حافظه‌ای (تک‌نمونه‌ای)، بدون HTTPS مدیریت‌شده خودکار، و پایش امنیتی ۲۴/۷ لازم است. استقرار شخصی/شبکه مورد اعتماد: OK.
2. یادآوری زنده به باز بودن تب/PWA وابسته است؛ پوش تضمینی نیازمند Web Push (VAPID) — مستند: `docs/REMINDERS_PLATFORMS.md`.
3. اتصال‌های بیرونی (ایمیل/تقویم/تلگرام/واتساپ) طراحی و مستندند ولی غیرفعال — نیازمند حساب و تصمیم مالک: `docs/CONNECTIONS.md`.
4. گفتگو یک تاریخچه مشترک دارد (threads نیست).
5. Web Speech (ورودی/خروجی صوتی) به پشتیبانی مرورگر وابسته است.
