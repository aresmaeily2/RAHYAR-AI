# معماری موبایل رهیار AI — مقایسه و توصیه (بخش ۹ دستور)

> اصل دستور: هسته فعلی وب حفظ شود مگر شواهد فنی خلافش را ثابت کند؛
> کم‌تغییرترین معماری‌ای که نیازهای واقعی را برآورده کند.

## مقایسه چهار مسیر

| معیار | PWA به‌تنهایی | Capacitor + وب هسته | اپ Android + پل امن | RN / Flutter (بازنویسی) |
|--------|--------------|---------------------|----------------------|--------------------------|
| هزینه توسعه | تقریباً صفر (انجام شد) | کم (wrapper + پلاگین‌ها) | متوسط | بسیار زیاد |
| حفظ کد فعلی | کامل | کامل (همان build وب) | UI دوباره | صفر — بازنویسی کامل |
| اعلان پس‌زمینه واقعی | فقط با Web Push (نیاز VAPID) | ✓ پلاگین Push/LocalNotifications | ✓ کامل | ✓ کامل |
| صدای یادآوری مطمئن | محدود (تب باز) | ✓ بومی | ✓ بومی | ✓ بومی |
| دسترسی مخاطبین/تماس | محدود (tel: link) | ✓ با مجوز کاربر | ✓ با مجوز | ✓ با مجوز |
| انتشار | نصب مستقیم/URL | APK/Play Store | APK/Play Store | هر دو سکو جدا |
| ریسک تخریب UX فعلی | صفر | کم | متوسط | زیاد |

## توصیه نسخه اول: PWA (پیاده شده) + مسیر Capacitor به‌عنوان فاز ۲

**دلایل:**
1. هسته وب کامل است: RTL، تم، آفلاین‌مانند، موبایل‌پسند — بازنویسی منفعت ندارد.
2. `manifest.ts` + `sw.js` همین حالا نصب‌پذیری پایه را می‌دهد.
3. گلوگاه واقعی (اعلان پس‌زمینه تضمینی) با Web Push قابل حل است بدون ترک وب:
   - گام‌ها: کلید VAPID (تصمیم مالک) → ثبت اشتراک کلاینت → ارسال پوش از سرور
     در زمان یادآوری → `notificationclick` در sw.js.
4. اگر نیاز بومی جدی شد (پوش مطمئن، مخاطبین، تماس): **Capacitor** کم‌تغییرترین
   مسیر است چون همین build وب را با پلاگین‌های بومی می‌پوشاند — نه بازنویسی.

## نمونه کوچک قابل‌آزمایش قبل از افزودن چارچوب (الزام دستور)
قبل از هر ادغام Capacitor، این سه آزمون روی یک شاخه جدا:
1. اعلان بومی: `LocalNotifications.schedule()` برای یک یادآوری آزمایشی.
2. صدا: پخش در حالت پس‌زمینه با `keepAwake`/کانال اعلان.
3. پل امن: فراخوانی `/api/tasks` از WebView با کوکی نشست موجود.

هیچ‌کدام تا وقتی مالک تأیید نکند شروع نمی‌شود.

## اندروید — قواعد (وقتی ساخته شود)
- اعلان فقط با انتخاب و مجوز روشن کاربر (opt-in)؛ رد مجوز = اپ کامل کار می‌کند.
- کمینه‌سازی متن اعلان: عنوان کوتاه + پیام یادآوری؛ بدون عنوان کار حساس به انتخاب پیش‌فرض.
- پاسخ پیشنهادی و بازکردن برنامه مقصد فقط با deep link معلوم.
- مخاطبان و تماس فقط از مسیرهای مجاز سیستم‌عامل (ContactPicker / ACTION_DIAL با تأیید کاربر).
- امکان لغو مجوز از تنظیمات و «حذف داده‌های جمع‌آوری‌شده» در صفحه اتصال‌ها.

## iOS — قواعد
- فقط قابلیت‌های رسمی: اعلان با UNUserNotificationCenter، بازکردن شماره‌گیر با tel:.
- محدودیت‌های پس‌زمینه/اتوماسیون جدا مستند می‌شوند؛ هیچ وعده دسترسی به پیام‌های
  سایر اپ‌ها یا کنترل سایر برنامه‌ها داده نمی‌شود.
- Accessibility به‌عنوان راهکار عمومی خواندن/کنترل برنامه‌ها استفاده نمی‌شود.
