## ۱. اصل صادقانگی — ادعاهای اصلاح‌شده

| فایل | ادعای قبلی (نادرست) | متن اصلاح‌شده |
|---|---|---|

| `RahyarBridge.java` | «صدا هیچ‌گاه ذخیره یا ارسال نمی‌شود» | همان متن صادقانه + اشاره به voiceSttState |

| `HomeActivity.java` | «صدا هرگز ذخیره/ارسال نمی‌شود» | متن صادقانه |
| `app.js` (کامنت بلوک صوت ×۱، متن privacy تنظیمات fa/en، wakeDesc fa/en) | «هیچ ذخیره یا ارسال صدا انجام نمی‌شود» / «ذخیره یا ارسال پنهان صدا وجود ندارد» | متن صادقانه: «صدا به سرویس گفتار سیستم‌عامل می‌رود؛ بسته به دستگاه روی‌دستگاه یا آنلاین» |
| `speech.ts` | «صدا هرگز روی سرور ارسال یا ذخیره نمی‌شود» | مرورگر ممکن است آنلاین پردازش کند (مثلاً Chrome)؛ رهیار روی سرورِ خودش ذخیره/ارسال نمی‌کند |
| `AndroidManifest.xml` (کامنت RECORD_AUDIO) | «هیچ‌گاه ذخیره یا ارسال نمی‌شود» | متن صادقانه |
| اعلان Wake (strings wake_body fa/en) | «هیچ صدایی ذخیره یا ارسال نمی‌شود» | متن صادقانه |

## ۲. معماری مسیر تشخیص (جدید)

- **on_device** (API 31+، در صورت موجود بودن): `createOnDeviceSpeechRecognizer` — صدا از دستگاه خارج نمی‌شود؛ در UI: «موتور تشخیص: روی‌دستگاه — صدا از دستگاه خارج نمی‌شود»
- **system_service** (مسیر عمومی): ممکن است آنلاین پردازش کند؛ **فقط با رضایت صریح** (`stt_online_consent`)؛ دیالوگ بومی با متن شفاف؛ رد/لغو = هیچ شنودی؛ در UI: «ممکن است آنلاین پردازش کند» + دکمهٔ اجازه/لغو
- **unavailable**: وضعیت صادقانه، هیچ شنودی
- تصمیم هر درخواست خالص و JVM-آزمون‌شده است (`sttStartDecision`)

## ۳. سیاست نگهداری داده

- صدا: **هیچ ذخیره‌سازی** — `onBufferReceived` unused؛ هیچ فایل/DB صوتی در اپ نیست؛ هیچ مسیر ارسال از اپ به هیچ سروری برای صدا وجود ندارد
- متن transcript: فقط در حافظهٔ UI (panel) — ذخیرهٔ پایدار ندارد
- کلیدهای prefs صوتی: `wake_restore_pending` (bool)، `stt_online_consent` (bool) — فقط boolean، بدون هیچ دادهٔ کاربر
- لاگ بومی: فقط کدهای گیت/نام کلاس استثنا (`Log.w("RahyarWake", ...)`) — بدون متن گفتار/دادهٔ کاربر؛ متن گفتار به لاگ سیستمی نمی‌رود

## ۴. سرویس پس‌زمینه و شنود پنهان

- با R3-P1 بیدارباش غیرفعال است → **هیچ شنود پس‌زمینه‌ای وجود ندارد**؛ اعلان گمراه‌کنندهٔ «در حال شنود» هرگز ساخته نمی‌شود (گیت + try/catch)
- از BOOT هیچ سرویس میکروفونی شروع نمی‌شود؛ فقط پیام وضعیت در اپ
- لغو مجوز در حین اجرا → توقف فوری سرویس
- Push-to-talk: شنود فقط با لمس کاربر؛ پایان خودکار با onResults/onError/لغو کاربر

## ۵. APK و کلیدها

- هیچ API Key اختصاصی در APK نیست (گزینهٔ Porcupine عمداً به‌همین دلیل رد شد — سند تصمیم Wake)
- مجوزها: همان ۹ مجوز قبلی (INTERNET، POST_NOTIFICATIONS، SCHEDULE_EXACT_ALARM، RECEIVE_BOOT_COMPLETED، VIBRATE، RECORD_AUDIO، FOREGROUND_SERVICE، FOREGROUND_SERVICE_MICROPHONE، RECEIVE_SMS) — بدون افزایش
- INTERNET فقط برای ماژول اختیاری اتصال به سرور مالک

## ۶. بندهای باز (صادقانه)

1. رفتار واقعی موتور روی دستگاه (روی‌دستگاه بودن یا نه، کیفیت فارسی، تاخیرها) = BLOCKED بدون دستگاه — ادعایی ثبت نشده
2. بازبینی مجدد پس از بازفعال‌سازی Wake Word (نیاز به رضایت + اندازه‌گیری — سند تصمیم)
3. آزمون رضایت روی دستگاه بدون موتور on-device (مسیر dialog بومی) — BLOCKED
