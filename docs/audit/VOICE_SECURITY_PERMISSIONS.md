# VOICE_SECURITY_PERMISSIONS — امنیت، مجوزها و حریم خصوصی صوت (V1)

- **تاریخ:** 2026-11-08 · **HEAD کد:** `1e15165`

## ۱. مجوزهای اندروید (Manifest واقعی build — `android/app/gradle/AndroidManifest.xml`)

| مجوز | دلیل | حداقل‌بودن |
|---|---|---|
| `RECORD_AUDIO` | فقط برای تشخیص گفتار با رضایت صریح (دکمهٔ میکروفون/Wake با رضایت) | ✓ — صدا به سرویس گفتار سیستم می‌رود |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE` | فقط سرویس اختیاری Wake Word با اعلان ماندگار شفاف | ✓ — foregroundServiceType="microphone" |
| `POST_NOTIFICATIONS`، `SCHEDULE_EXACT_ALARM`، `RECEIVE_BOOT_COMPLETED`، `VIBRATE` | یادآور سیستمی + باززمان‌بندی بوت | خارج از مأموریت صوت — قبلاً ممیزی F5/F7 |
| `RECEIVE_SMS` | فقط مسیر پیامک بانکی با رضایت (مأموریت ۷ پیشین) | خارج از مأموریت صوت |
| `queries` | کشف سرویس RecognitionService/TTS_SERVICE (اندروید ۱۱+) | ✓ لازم برای SpeechRecognizer/TTS |

هیچ مجوز اضافه‌ای (مخاطب/موقعیت/ذخیره‌سازی/تلفن) برای صوت وجود ندارد.

## ۲. جریان رضایت میکروفون (هر دو حالت)

- **درخواست زمان‌اجرا:** اولین لمس میکروفون → `micState` (granted/denied/need_request) → `requestPermissions(RECORD_AUDIO, 4701)` → نتیجه → رویداد `rahyar-voice-perm` → وب دوباره تلاش می‌کند یا پیام صادقانه می‌دهد.
- **رد مجوز:** `denied` → هیچ شنودی شروع نمی‌شود؛ پیام محلی fa/en.
- **لغو از تنظیمات گوشی:** در هر `startListening` وضعیت مجوز دوباره چک می‌شود (`VoiceHelper.java:121-131`) → deny فوری، بدون کرش.
- **Wake Word:** پیش‌فرض خاموش؛ روشن‌کردن فقط از تنظیمات اپ با توضیح شفاف + اعلان ماندگار؛ خاموش‌کردن = توقف کامل سرویس؛ بازیابی بوت فقط با `wakeWord:true` صریح در پروفایل (fail-closed — JSON خراب/نبود = خاموش؛ `BootReceiver.wakeEnabledFromProfileJson`).

## ۳. عدم شنود پنهان و عدم ارسال صدا

- شنود فقط با اقدام کاربر شروع می‌شود؛ پایان با پایان جمله یا تاپ کاربر.
- `onBufferReceived` no-op — **هیچ بافر صدا ذخیره یا ارسال نمی‌شود**؛ پردازش صدا داخل سرویس گفتار سیستم‌عامل است.
- Wake: شنود پیوسته فقط برای دیدن عبارت بیدارباش؛ پس از تشخیص، فقط اپ باز می‌شود؛ **هیچ متن/صدایی ذخیره نمی‌شود**.
- **Logcat:** هیچ محتوای صوتی/فرمانی لاگ نمی‌شود (کلاس‌های صوتی هیچ console.log/log.d ندارند — بازبینی V1).
- TTS: فقط متن پاسخ؛ سقف ۶۰۰ نویسه در پل (`MAX_SPEAK_CHARS`) — جلوگیری از خواندن حجم زیاد.

## ۴. کلیدها و APK

- **هیچ API Key در APK نیست** — کلیدهای AI فقط سرور (Setting جدول، masked در GET)؛ APK فقط WebView/محلی است.
- APK v2.4.0 با `apksigner verify` بررسی شد — فقط امضای Release V1 (`CN=RahyAr Release V1`) یا Debug؛ بدون secret.
- پل JS: هیچ مسیر فایل/توکن/نشست در دسترس JS نیست؛ ناوبری WebView قفل است.

## ۵. تأیید پیش از عملیات حساس صوتی

- مالی/حذف در وب: ماشین پندینگ + تأیید صریح (اثبات زنده: پیشنهاد بدون نوشتن → تأیید نام‌دار → نوشتن دقیق؛ انصراف → صفر تغییر).
- مالی/حذف در حالت محلی: `askConfirm` — بدون «بله» هیچ نوشتنی (JVM: delete همیشه confirm=true).
- **پاسخ مدل هرگز موفقیت را جعل نمی‌کند** — پیام موفقیت فقط پس از `ok=true` واقعی DB/سرویس صادر می‌شود (مسیر قطعی مالی F7 حفظ شده).

## ۶. سرعت/زبان صوتی — اعتبارسنجی ورودی

- `voice_rate` سرور: فقط ۰٫۵–۲٫۵ (خارج → HTTP 400 — آزمون زندهٔ S7).
- پل بومی `setTtsRate`: sanitize JVM (خارج بازه/غیرعددی → بی‌اثر) + تست.
- `voice_lang`: فقط ''|fa|en.

## ۷. چیزهایی که عمداً انجام نشد

- ارسال صدا به هر سروری (حتی Provider ابری TTS/STT) — پیاده نشد؛ در صورت درخواست مالک باید هزینه/حریم/کلید شفاف مستند شود.
- ذخیرهٔ هر فایل صوتی — وجود ندارد؛ «پاک‌سازی داده‌های صوتی» از اساس موضوعیت ندارد (هیچ دادهٔ صوتی ذخیره نمی‌شود) و همین در UI محلی اعلام شده است.
