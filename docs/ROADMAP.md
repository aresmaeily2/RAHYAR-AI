# نقشه راه رهیار AI

وضعیت هر آیتم: ✅ انجام‌شده | 🚧 نیمه‌تمام | ⬜ برنامه‌ریزی‌شده (نیازمند تصمیم/منبع)

## افق کوتاه (نسخه بعد)

- 🚧 **پوشش موبایل کامل**: PWA آماده است (manifest + SW مینیمال)؛ گام بعد: بسته‌بندی Capacitor با کانال داخلی + آزمون روی دستگاه اندروید واقعی — طرح: `docs/MOBILE_ARCHITECTURE.md`
- ⬜ **Web Push برای یادآوری**: نیازمند کلیدهای VAPID و تصمیم مالک (پلتفرم‌ها: `docs/REMINDERS_PLATFORMS.md`)
- ⬜ **پاک‌سازی تاریخچه گیت** از بلاب‌های حساس قدیمی (`.env/db` قدیمی، بدون کلید API) — فقط با تأیید مالک و قبل از هر push
- ⬜ **پشتیبان خودکار زمان‌بندی‌شده**: اجرای `backup-db.sh` از خود زمان‌بند سرور + نگهداری N نسخه

## افق میانی

- ⬜ **اتصال واقعی ایمیل/تقویم با OAuth**: چارچوب مجوز/لغو/حذف/پیش‌نمایش در `docs/CONNECTIONS.md` تعریف شده؛ اجرا نیازمند ثبت OAuth App و کلاینت‌سکرت خارج از سندباکس
- ⬜ **تلگرام رسمی (Bot API)**: یادآوری به چت تلگرام — توکن بات در `.env`؛ ساختار داده آماده است
- ⬜ **WhatsApp Business Cloud API**: نیاز به حساب بیزینسی متا و بازبینی قالب پیام
- ⬜ **ارائه‌دهنده دوم مدل** به‌عنوان fallback *دستی* (خاموش به‌صورت پیش‌فرض — سیاست بدون مسیر پولی خودکار)
- 🚧 **چندنمونه‌ای**: انتقال rate-limit و زمان‌بند به استور مشترک (SQLite/WAL یا Redis)

## افق بلند

- ⬜ همگام‌سازی چنددستگاهی با حساب شخصی (نسخه سرور + کلاینت موبایل)
- ⬜ گزارش هفتگی تحلیلی قطعی (روند تکمیل، تمرکز، عقب‌افتادگی)
- ⬜ بازارچه افزونه عاملیت با رضایت صریح برای هر قابلیت جدید

## اصل ثابت نقشه راه

1. هیچ مسیر پولی خودکار/مخفی اضافه نمی‌شود؛ هر هزینه جدید فقط با رضایت مالک و کلید صریح.
2. داده کاربر فقط و فقط مالک خودش — هیچ API اشتراکی بدون رضایت صریح.
3. هر قابلیت جدید باید آزمون واحد + آزمون زنده داشته باشد؛ «شاهد واقعی برای هر ادعا».
