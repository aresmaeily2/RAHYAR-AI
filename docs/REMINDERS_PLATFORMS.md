# یادآوری و اعلان — تفاوت پلتفرم‌ها و محدودیت‌های صادقانه

> بخش ۸ دستور اجرایی: هیچ ادعایی درباره پخش صدای تضمین‌شده در همه شرایط پس‌زمینه نمی‌کنیم.

## چیزی که الان واقعاً کار می‌کند (نسخه فعلی)

| قابلیت | وضعیت | شرط کارکرد |
|---------|-------|-------------|
| زمان‌بندی یادآوری در دیتابیس سرور | ✓ کار می‌کند | پروسه سرور فعال باشد |
| هشدار داخل اپ (توست) | ✓ | تب رهیار باز باشد (polling هر ۳۰ ثانیه) |
| صدای انتخابی (۳ پروفایل WebAudio) | ✓ | تب باز + کاربر قبلاً با اپ تعامل کرده (سیاست autoplay مرورگرها) |
| گفتار محلی فارسی (Web Speech API) | ✓* | صدای فارسی روی دستگاه نصب باشد؛ عدم وجود → فقط متن |
| اعلان مرورگر (Notification API) | ✓ | مجوز داده شده + تب باز باشد |
| منقضی‌سازی یادآوری پشت‌مانده | ✓ سروری | پنجره هشدار ۱۵ دقیقه؛ سپس ActionLog «failed» |

## محدودیت‌های سکو — صادقانه

### وب (تب مرورگر)
- مرورگرِ بسته = هیچ اعلانی. polling به تب زنده وابسته است.
- پس‌زمینه تب: مرورگرها تایمر را کند می‌کنند (تا چند دقیقه تأخیر ممکن).

### PWA نصب‌شده
- Android (Chrome): با نصب PWA، اعلان‌ها سرویس‌ورکری می‌شوند؛ کارکرد پس‌زمینه
  واقعی نیازمند **Web Push (VAPID)** است — عمداً پیاده نشده چون کلیدها و
  تصمیم مالک لازم دارد. مسیر آماده: `public/sw.js` موجود است، افزودن
  `push` + `notificationclick` + ثبت اشتراک سمت سرور کافی است.
- iOS (Safari ≥16.4): اعلان وب فقط برای PWA نصب‌شده به Home Screen و فقط با
  مجوز صریح؛ محدودیت‌های اپل درباره پردازش پس‌زمینه سخت‌گیرانه‌تر است و
  تضمین زمان دقیق وجود ندارد.

### اپ بومی (Android/iOS)
- اعلان بومی زمان‌بندی‌شده (AlarmManager/UNNotificationTimeInterval) قابل‌اتکاتر
  است ولی توسعه بومی جداگانه می‌خواهد — مقایسه کامل: `docs/MOBILE_ARCHITECTURE.md`.
- iOS: هیچ مسیر رسمی برای اجرای آزاد پس‌زمینه یا خواندن پیام‌های سایر اپ‌ها
  وجود ندارد؛ رهیار چنین وعده‌ای نمی‌دهد.

## صدای ابری (TTS)
- عمداً فعال نیست: هزینه + ارسال متن خصوصی به سرویس ابری.
- در صورت تمایل مالک، در آینده به‌صورت opt-in با سقف مصرف جداگانه اضافه می‌شود.

## زمان‌بندی سمت سرور — واقعیت فعلی
`src/lib/reminders/scheduler.ts` با پروسه Next سرور می‌چرخد (هر ۶۰ ثانیه):
- منقضی‌سازی یادآوری پشت‌مانده + هرس نشست + respawn کار تکرارشونده.
- اگر سرور خاموش باشد نمی‌چرخد؛ برای اطمینان بالا، cron خارجی یا پوش لازم است
  (تصمیم و پیکربندی مالک).
