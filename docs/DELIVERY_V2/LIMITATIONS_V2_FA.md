# محدودیت‌های باقی‌مانده — RahyAr v2.0.0 (شفاف و کامل)

## ۱) محدودیت‌های محیط ساخت (نه نقص محصول)

| محدودیت | اثر | راه‌حل |
|---|---|---|
| نبود دستگاه اندروید/adb/KVM | هیچ قابلیتی «آزموده‌شده روی دستگاه» اعلام نمی‌شود؛ سطح قابلیت‌های اندروید = کد + JVM + build موفق | چک‌لیست ۱۵ دقیقه‌ای مالک در ماتریس قابلیت‌ها |
| پایان‌یافتن پروسه‌های پس‌زمینه بین فرمان‌ها در sandbox | استقرار پایدار در محیط ساخت ممکن نیست؛ آزمون‌های زنده به‌صورت جلسه‌ای اجرا شدند | استقرار روی هاست مالک (راهنمای ۵ دقیقه‌ای ارائه شد) |
| نبود اعتبارنامهٔ گیت‌هاب (PAT/SSH) پس از ریست محیط | push به `aresmaeily2/RahyAr` انجام نشد — بدون ادعای نتیجه | بستهٔ سورس + دستور push دقیق تحویل شد؛ با PAT جلسهٔ بعد فوراً push می‌شود |
| rate-limit پایدار gofile.io در این جلسه | لینک دائمی APK فعلاً از tmpfiles.org (۶۰ دقیقه) + بستهٔ محلی | تلاش مجدد gofile؛ یا Release گیت‌هابی پس از push |

## ۲) تصمیم‌های نیازمند مالک

| موضوع | گزینه‌ها | اثر |
|---|---|---|
| کلید release اندروید | ساخت keystore جدید (پیشنهاد) / ادامه با debug برای آزمون | انتشار فروشگاهی نیازمند کلید پایدار است |
| دریافت خودکار پیامک بانکی (`RECEIVE_SMS`) | فعال‌سازی با رضایت صریح / ماندن روی ورود دستی | سیاست پلی‌استور + الزامات قانونی؛ فعلاً عمداً غیرفعال |
| مجوز عملیاتی مدل میزبان (zai) برای کاربران واقعی | بررسی شرایط سرویس + تنظیم سهمیه‌ها | چت AI رایگان-بدون‌کلید فعال است؛ برای عموم، مرزها را مالک تعیین می‌کند |
| اتصالات OAuth بیرونی (ایمیل/تقویم/پیام‌رسان/مخاطبین) | تامین کلید/پیکربندی مالک | فعلاً صرفاً طراحی‌شده (کاتالوگ) |

## ۳) محدودیت‌های فنی شناخته‌شده

| موضوع | توضیح | تخفیف |
|---|---|---|
| تشخیص گفتار اندروید به سرویس گفتار دستگاه وابسته است | روی گوشی‌های بدون سرویس Google گفتار، `unavailable` برمی‌گردد و toast شفاف نمایش داده می‌شود | پیام خطا + مسیر تایپی همیشه فعال |
| اعلان دقیق روی برخی لایه‌های سبک Chinese OEM | Android ممکن است BootReceiver/alarms را به تعویق بیندازد | fallback inexact + هشدار درون‌برنامه‌ای وب (پنجرهٔ ۱۵ دقیقه) |
| TTS فارسی بستگی به موتور TTS نصب‌شده دارد | اگر صدای فارسی نباشد، خواندن انگلیسی/پیش‌فرض یا خطا | صدای سیستم قابل نصب است |
| استریم مدل میزبان از نظر آپ‌استریم دسته‌ای است | SSE خروجی به کاربر واقعاً جریانی است؛ آپ‌استریم یک درخواست است | بی‌اثر برای تجربهٔ کاربر |
| «تکمیل و تأییدشده» سرور-محور است | یعنی آزمون زندهٔ API/UI؛ نه آزمون گوشی | جدول ماتریس صادقانه تفکیک کرده |
